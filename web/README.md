# Веб-морда: обучение и генерация

Два раздела: «Обучение» (склонировать голос с микрофона или файла и обучить
модель) и «Генерация» (текст → звук, история справа). Сервис
`silero_tts` (HTTP 10500 / wyoming 10501) не трогается — он остаётся для
Home Assistant и колонки; морда генерирует своим движком.

    браузер ── :10580 ── web/app.py (FastAPI + static/)
                      ├── web/engine.py   свой движок: стоковые + обученные
                      │                   модели, LRU-кэш, синтез на CPU
                      ├── web/refprep.py  опора: декодирование, чистка, ударения
                      ├── web/jobs.py     обучение подпроцессами train/*
                      └── web/store.py    реестр моделей, история (только файлы)

## Запуск

    scripts/deploy.sh            # код на сервер (морда входит в дерево)
    scripts/web.sh restart       # сборка образа silero_web и подъём

Образ `silero_web` = `silero_ru` + FastAPI. Контейнеру нужны `gpus: all`
(ступени обучения) и `network_mode: host` (gigaam 127.0.0.1:10407 для
проверки CER, HF-кэш для F5). Данные морды живут в `/w/web/`:

    models/<id>/   meta.json, ref/, f5/, targets/, train/, preview.wav
    history/       index.json + <имя голоса>_<дата>.wav
    uploads/<id>/  исходник загрузки и приготовленная опора
    jobs/<id>.json состояние задач (переживает перезапуск)

## Обучение

1. Опорная запись: микрофон (браузер собирает WAV 48 кГц моно сам, без
   webm) или файл wav/mp3/flac/ogg — `refprep.decode` идёт по цепочке
   soundfile → torchaudio → ffmpeg.
2. `refprep.clean`: границы речи по звонким кадрам pyin + энергии
   (урок SILERO.md шага 2), паузы внутри сжаты до 0.3 с, края 0.2 с,
   пик −3 dBFS. Текст размечается silero-stress и показывается для правки.
3. Режимы: **проба** (~24 фразы, ступень 1, голос-черновик, ~3 мин) и
   **полное** (весь RUSLAN, ступени 1–2 + просодия + приёмка, ~27 мин).
   Проба и полный прогон делят каталог модели, поэтому «продолжить до
   полного» доозвучивает только хвост (манифесты f5.jsonl и готовые .pt
   пропускаются).
4. Прогресс — разбор stdout ступеней (`jobs.parse_line`), одна задача на
   GPU, вторая ждёт в очереди. Отмена убивает подпроцесс.

Готовая модель автоматически попадает в список голосов генерации.

### Вписать уже обученную модель

Боевую модель сервиса или любой готовый .pt можно зарегистрировать без
переобучения — файл подключается симлинком, сразу озвучивается превью:

    docker exec silero_web python -m web.register /w/train/model_voice.pt \
        --name artur

`msc` для ручки тональности возьмётся из `/w/targets/stats.pt`.

## Генерация

Ручки: скорость (`durs_rate` в `predict`), тональность в % от F0
(через `mean_std_coef`, как SSML-просодия у Silero), пауза на точке
(`cap_pauses`), пауза между фразами, числа словами, свои ударения
(`accent=0`), частота выхода. Всё по умолчанию — как у модели. «|» в тексте
— принудительный разрыв фразы. Выпавшие из алфавита символы показываются
плашкой «ВНЕ АЛФАВИТА».

История хранится на сервере, файл называется `<имя голоса>_<дата>.wav`,
имя берётся на момент генерации. «Повторить» подставляет текст, голос и
настройки записи.

## Проверка ручек

Семантика `durs_rate`/`pitch_coef` выведена из вскрытия; на живой модели её
сверяет `docker exec silero_web python -m web.check_knobs` — сравнивает наш
путь с `apply_tts(speech_rate=…)` и печатает вердикты.
